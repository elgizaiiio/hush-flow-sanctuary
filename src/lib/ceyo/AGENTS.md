- Active chat, inline specialists and text summaries use the shared Cerebras Chat Completions adapter and active provider-key pool. Do not route text generation through Lovable AI Gateway.
- Speech-to-text and other audio/media operations remain on their dedicated provider integrations unless Cerebras explicitly supports the required audio API; do not confuse an audio gateway or Git connector with text-model inference.
- Shared usage availability checks use the caller's owner-scoped client before provider-token access; costly discrete audio/vision operations also debit atomically. Why: exhausted accounts must not bypass chat limits through media endpoints; token gating is not continuous-session metering.
- Recompute replyLanguageInstruction from the latest user message at each agent-loop step, after persona and saved context; people-bot uses the invoking member's message. Why: language switches, tool outputs and other participants must not override the current user's language or dialect.
- Cerebras tool calls use the existing OpenAI-compatible SSE parser with `reasoning_effort: "medium"` for agent turns (low gave shallow, manual-instruction answers); one-shot replies such as hosted Telegram bots stay "low".
- The agent loop holds each step's text until the step ends, nudges a first-answer refusal once, a technical ask (IDs/code/API steps) once and printed tool calls at most twice, and cooling Cerebras keys are reused only when no ready key exists. Why: act-first behavior without unbounded usage or false "not configured" failures.
- Agent-published web pages are agent_documents rows served by /api/public/site/$siteId with a CSP sandbox header. Why: user-generated HTML gets a live link without reading the app's session or storage.
- Hosted Telegram bots save every received update to the owner-only telegram_inbox (30-day retention); personal Telegram Business chats are answered only when business_reply is on. Why: the agent reads the user's messages without storing the bot token or replying on their behalf uninvited.
- Agent turns end with a tool-free final step and a wrap-up note near the step budget; blocked-site reads get a switch-source note. Why: big tasks must deliver a result instead of failing at the limit or trusting anti-bot pages.
- Text and agent turns go through cerebrasRequest/getCerebrasKeys: provider_api_keys rows with provider "coarena" are tried first (CoArena OpenAI-compatible endpoint, model COARENA_MODEL), then Cerebras keys with CEREBRAS_MODELS.text; any CoArena failure falls through to Cerebras without waiting. Tool names sent to the model must be unique. Never hardcode model ids in the loop or bot defaults, and trim whitespace-only step text. Why: one switch per provider, strongest model first with a free fallback, and CoArena rejects duplicate tool names.
